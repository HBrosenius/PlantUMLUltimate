WRITTEN LESSON

Mindmaps: from a topic
to a tidy map.

A text walkthrough for mindmap diagrams. There is no video for this lesson yet, so each step names the control to use and the source it writes. Back to the course index.

1. Create a mindmap

Choose New diagram tab, pick Mindmap and select a starter. A mindmap has one or more roots written with *; each extra * goes one level deeper. 

@startmindmap
* Product launch
** Plan
*** Budget
** Build
@endmindmap

2. Edit in the preview

Click a node to open the inspector: label, colour, text colour, style class, box, side, link and icon. Use Insert → Mindmap node for a child or a sibling. Drag a node above or below another to reorder it, onto the middle of one to nest it, or beside the root to move it to the other side. Every edit is one undo step.

3. Both sides of the root

++ places a first-level branch on the right and -- on the left. A left side line moves every following ** branch to the left until a right side line. Add _ after the markers, as in **_ Notes, for a node without a box. Direction lines such as top to bottom direction turn the whole map.

4. Edit several nodes at once

Shift-click or Ctrl/⌘-click nodes to select them (Ctrl/⌘+A selects all while the map has focus). The Selected elements inspector sets a colour or a style class on all of them, removes or adds their boxes, or deletes them with their branches after you confirm. A node selected together with its parent goes with that parent, and at least one root always stays. Each bulk action is a single undo step.

5. Style blocks

In the source editor, type <style and pick a snippet: a plain block, a style class (.green, applied with <<green>> on a node), a depth rule (:depth(1)) or a maximum width for long labels. 

<style>
mindmapDiagram {
  .green {
    BackgroundColor lightgreen
  }
}
</style>
Avoid a * {} rule

The PlantUML engine reads a * { line in a style block as a node and stops with an error. The editor flags it with a warning and a quick fix that writes node { instead.

6. Markdown-form mindmaps

PlantUML also accepts # headers and indented * bullets. Mindmaps written that way stay source-only. Use the Convert to * markers quick fix on the info message (Ctrl/⌘+.), or the button in the node or Mindmap settings inspector, to switch to the standard form and edit visually.

Practice

Try these in order: build the map above, move Budget under Build by dragging, select two nodes with Shift-click and give them a colour, then paste a # Root / ## Child source and convert it.

Mindmap support needs a current build; older builds cannot open projects that contain a mindmap.
