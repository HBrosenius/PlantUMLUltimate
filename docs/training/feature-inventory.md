# Training feature inventory and coverage map

Inventory date: 30 October 2026. Source baseline: `dae6153`, plus the existing working tree. This is a training scope audit, not a functional acceptance test. No application source was changed for this audit.

## Result

The twenty-lesson structure still works, but the original 202-minute budget omitted teaching time for several substantial features. Reserve **222 minutes (3 hours 42 minutes)**: reports increase from 10 to 20 minutes, saving/recovery from 8 to 12, and final handover from 8 to 14. Confirm pacing with the pilot. The 105 coverage units below group related controls; they are not a count of individual buttons or all PlantUML syntax variants.

Material additions: all eight report types; explicit historical observations; multi-selection and bulk editing; custom starters; presentation, named views, and personal review notes; portable-file compression and encryption; document history limits; PDF export; copy formats; and encoded renderer links. These now have explicit teaching destinations. A follow-up review added seven units for behavior changed on 26–27 October: syntax-error recovery, preview layout, task-delete pinning, the dependency lag rule, collaboration room lifetime, partial Jira publishing and diagram link confirmation.

The source review produced a supplemental index of **79 graph-linked UI source files and 1,688 label fragments**. Label fragments include headings, options, and explanatory text; this number is not a feature count. The live pass captured **31 surfaces**: four ribbon categories for each of seven diagram types, File, File → Export, and Reports. Seeing a control establishes its presence, not that its entire workflow works.

Evidence artifacts, relative to the repository root:

- `output/training-inventory/source-controls.json`: exact source locations, fragments, graph definition ranges, and file hashes.
- `output/training-inventory/runtime-surfaces.json`: visible text and controls from the current-source development server, with capture timestamp.
- `output/training-inventory/reports.png`: Reports panel evidence.
- `output/training-inventory/probe.mjs`: repeatable runtime menu inventory.
- `docs/training/feature-inventory.csv`: editable copy of the coverage units below.

## How to read the checklist

Every ID is a planned scene group: for example, `R03` becomes lesson `07`, scene group `R03`. The **show / verify** column defines what the learner should see and what the recording rehearsal must confirm.

- **UI**: entry point or options observed in the running app, with source/documentation context where needed. End-to-end behavior remains to rehearse.
- **SRC**: identified in graph-linked source definitions; detailed workflow rehearsal pending.
- **DOC**: documented behavior; confirm against the recording release before scripting detailed claims.
- **T**: teach through a worked demonstration. **G**: grouped demonstration of related settings or variants. **R**: reference material plus an in-lesson example.

All rows currently have **recording validation pending**. None is marked as taught or production-ready. Features with browser, service, or account dependencies remain in scope and have explicit prerequisites below.
