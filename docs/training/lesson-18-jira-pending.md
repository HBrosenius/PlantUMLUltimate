## Recording sequence and narration draft

1. **Purpose and boundaries.** “Jira integration connects a reviewed plan with a chosen issue source. Work in a sandbox for this exercise. Confirm the site, project, credentials and intended issue scope before importing or publishing.” Show the integration entry point and explain credentials without displaying secrets.
2. **Connect and scope.** “Choose the intended site and project, and restrict the import to the small training issue set. Confirm that the account has the permissions the exercise needs.” Show the real connection and scope validation. Stop on a failed connection; do not substitute invented results.
3. **Import and mappings.** “Preview the proposed task mappings before accepting them. Check issue identity, summary, dates, progress and people where supported. Missing or unsupported fields need an explicit decision.” Import a small disposable issue set and compare the resulting source with Jira.
4. **Incoming and local changes.** “Change one supported field in Jira and another locally. Review the incoming and local differences before selecting a direction.” Record both genuine changes and the actual review.
5. **Conflict review.** “A conflict means that both sides changed relevant information. Inspect both values, preserve useful work and choose deliberately rather than treating synchronization as an automatic overwrite.” Create one controlled conflict and show the actual resolution controls.
6. **Publish preview.** “Publishing is a separate write operation. Read exactly which issues and fields would change, verify permissions and review the proposed result before applying.” Keep a before-state record and publish only the agreed disposable example.
7. **Partial outcomes.** “Read outcomes individually: confirmed means the write is known to have succeeded; rejected means it failed; uncertain means the result is not known; unattempted means it was not tried. Check an uncertain write in Jira before retrying, because repeating it blindly can duplicate or overwrite work.” Use a real supported outcome demonstration or label the explanation as a conceptual example; never force a failure in a shared project.
8. **Verification and cleanup.** “Verify the final values in Jira and the local plan, save the portable project and remove disposable data according to the sandbox rules.” Record verification, then document cleanup.

## Practice and success check

Given a disposable sandbox, import a bounded issue set, explain the mappings, create one local and one incoming change, review a conflict, and identify exactly which fields a publish would write. Explain all four partial outcome categories and the verification required before retrying an uncertain write.
