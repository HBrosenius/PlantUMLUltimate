## Bugs

### B1. High: deleting a linked WBS diagram makes the document unsavable

**Where:** `apps/web/src/projects/use-embedded-project.ts:336-363` (`deleteDiagram`).

**Cause:** deleting the WBS member leaves `wbsGantt.wbsDiagramId` on the linked Gantt member. `encodeProject` then runs `validateProject`, which rejects the dangling reference (`packages/document-format/src/validate.ts:452-459`).

**Repro:**

1. Run "Create WBS+Gantt document".
2. Delete the WBS diagram.
3. Save.

**Result:** the save throws `DocumentFormatError: diagrams[0].wbsGantt references an unknown WBS diagram`. Every later save fails the same way.

**Fix:** in `deleteDiagram`, drop the `wbsGantt` link from any member that points at the deleted id, and clear `linkedWbsDocumentId` on the open tab. Add a test that deletes the WBS member and saves.

### B2. High: Gantt `deleteTask` removes other tasks and leaves dangling references

**Where:** `packages/diagram-gantt/src/operations.ts:811-832`.

**Verified on:**

```
[A] lasts 2 days
[B] lasts 3 days and starts at [A]'s end
[A] -> [C]
[C] lasts 1 day
```

- **Delete A:** only `[C] lasts 1 day` remains. Task B is gone, because its whole line was removed.
- **Delete C:** `[A] -> [C]` is kept, so PlantUML re-creates C as an implicit task.
- **Also kept:** milestone references (`[M] happens at [A]'s end`) and `Separator just at [A]'s end`.

**Fix:**

- On another task's line, remove only the clause that refers to the deleted task (`and starts at [A]'s end`).
- Remove arrow lines whose successor is the deleted task, and rewrite chains (`[A] -> [B] -> [C]` without B becomes `[A] -> [C]`).
- Handle milestone and separator references the same way.

### B3. Medium: "N days after [A]'s end" is off by one

**Where:** `apps/web/src/gantt-schedule.ts:62-77` (`dependencyDate`).

**Cause:** an offset of 0 resolves to end + 1 (the next working day), but an offset of N resolves to end + N. So `starts at [A]'s end` and `starts 1 day after [A]'s end` give the same date.

**Effect:** with closed weekends, "2 days after" can land before "at end". `gantt-dependency-offsets.test.ts:11` codifies that ordering. Critical path, forecast and conflict checks can then disagree with the rendered chart.

**Before fixing:** render one example in PlantUML to confirm its semantics.

### B4. Medium: Gantt resize ignores allocation and pauses

**Where:** `apps/web/src/gantt-calendar.ts:138-176`, used by the resize drag at `DiagramPreview.tsx:954`.

**Cause:** `taskEnd` uses the raw duration, not the allocation-adjusted elapsed days or `taskPauses`.

**Example:** for `[A] on {Alice:50%} … lasts 4 days`, dragging +2 days shows "Ends 2026-10-10", but adds 2 duration days, which is about 4 calendar days.

**Fix:** derive the end and the delta from the same logic as `resolveTaskDates`.

### B5. Medium: moving a WBS subtree in a CRLF file does not change its depth

**Where:** `packages/diagram-wbs/src/operations.ts:224-232`.

**Cause:** the regex `/^(\s*)([*+-]+)(\s*.*)$/` fails on lines ending in `\r`.

**Verified:** moving A under B in `* Root\r\n** A\r\n** B` gives `** B\r\n** A`. A is reordered but not nested (expected `*** A`).

**Fix:** use `[^\r\n]*` instead of `.*`, or split on `\r?\n` and keep each line ending.

### B6. Medium: WBS subtree move rewrites lines inside multi-line labels

**Where:** same function as B5.

**Cause:** content lines that start with `-` or `+` are taken for node markers. For example, `***:Tasks\n- buy milk\n+ eggs;` moved one level deeper becomes `-- buy milk` and `++ eggs`.

**Fix:** rewrite only the marker lines, using the parser's per-node ranges.

### B7. Low–Med: the WBS boxless marker `_` is lost on edit

**Cause:** `**_ Boxless` parses with the label `"_ Boxless"`. `updateWbsNode` (`operations.ts:50-56`) then writes `** _ Boxless`, so any inspector edit removes the boxless style.

**Fix:** parse `_` as a flag and write it back.

### B8. Low–Med: overlapping saves show "cancelled" while a save is still running

**Where:** `apps/web/src/projects/use-single-file-project.ts:633-705`.

**Cause:** a second Save aborts the first. The first save's catch branch still passes `isCurrent()`, so it sets "Document save cancelled" while save #2 is in flight.

**Fix:** only update state when `saveAbort.current === controller`.

**Unconfirmed, timing-dependent:** a false `ProjectFileChangedError`, because `handleDigest` is updated after the coordinator releases. Set it inside the queued turn.

### B9. Low (unconfirmed): external reload check reads a stale dirty flag

**Where:** `apps/web/src/use-document-files.ts:537-605`.

**Cause:** `dirty` is read from a snapshot taken before an awaited file read. Keystrokes typed during the read can be replaced without a conflict prompt.

**Fix:** read the document again after the `await`.

### Minor

- **CRLF:** sequence and other deletes consume only `\n`, which leaves stray `\r` lines. WBS inserts add a bare `\n` to CRLF files.
- **Sequence participant rename:** it drops the indentation of rewritten message lines.
- **Fallback tab:** after the last tab closes, the new tab reuses `historyId: "history-welcome"` (`use-persisted-workspace.ts:180`). Unconfirmed in the UI.

## Security

Most earlier findings are fixed:

- **SVG sanitising:** `<style>` is now forbidden.
- **Renderer:** it runs in a sandboxed iframe with its own CSP, and messages are checked against both the source and a channel id.
- **Includes:** `!include` is blocked in every render path.
- **Collaboration:** credentials travel in `Sec-WebSocket-Protocol`, not the URL, and participant ids are assigned by the server.
- **Jira OAuth:** state is single-use and bound to a cookie.
- **Encryption:** PBKDF2 with 600k–2M iterations, a fresh IV on every encrypt, the header used as AAD, and a pinned tag length.
- **Zip import:** paths are checked for traversal, and size limits apply.

No new XSS, OAuth or encryption flaw was found.

### S1. Medium: joining a link without an access token uploads the active document

**Where:** `apps/web/src/collaboration-session.ts:181-186`.

**Cause:** `maySeedRoom = ownerToken || !accessToken`. Consider the link `#collaboration=<id>&server=https://evil.example` with no `access=`. If the user clicks Join, the client inserts the active tab's source into the empty room and streams every later edit there. The dialog does warn about a different server.

**Fix:** seed only when `ownerToken` is set. When joining, require `access=` and start from an empty document. Earlier audit item S3 recommended the same.

### S2. Medium: collaboration worker abuse and cost (still open)

**Where:** `apps/collaboration-worker/src/index.ts:185-195, 238-254, 309-319`.

**Problems:**

- A non-browser client can forge `Origin` and create unlimited persisted rooms, and rooms never expire.
- There is no cap on connections per room, and each presence message broadcasts the full participant list (O(N²)).
- Every update rewrites the full document, up to about 1.9 MB.

**Fix:**

- A connection cap per room.
- A per-socket token bucket.
- An idle alarm that calls `deleteAll()`.
- A Cloudflare rate-limit rule on `/rooms/*`.

### S3. Low–Med: the main CSP is weak (still open)

**Where:** `apps/web/index.html:9`.

**Problems:**

- `script-src` has `'unsafe-inline'` and `data:`, so any future HTML injection can run script.
- `connect-src https: wss: ws:` allows sending data to any host.
- GitHub Pages sends no `frame-ancestors` or `nosniff` header.

**Fix:** serve the renderer frame bootstrap as a same-origin file, then drop `data:` and `'unsafe-inline'`, and pin `connect-src` to the worker hosts.

### S4. Low: dependency advisories

`npm audit --omit=dev` flags DOMPurify 3.4.16 as critical. The current config (`render/sanitize-svg.ts:4-10`) does not meet any advisory's preconditions. Upgrade anyway with `npm audit fix`.

### S5. Low: `/api/connect-token` has no rate limit or body shape check

**Where:** `apps/integration-worker/src/index.ts:351-442`.

**Problems:**

- The worker can be made to fetch any `*.atlassian.net` host. This is bounded (no redirects), but it lets anyone probe credentials through the worker.
- A JSON body of `null` returns 503 instead of 400.

**Fix:** add a rate-limit binding and validate the body shape.

### S6. Low (unconfirmed): credentials in logs

The integration worker logs every request (`head_sampling_rate: 1`), including OAuth callback URLs. Check whether Workers Logs record the `Sec-WebSocket-Protocol` header, which now carries the room tokens.

### Still open from earlier audits

- No `__Host-` cookie prefix.
- Localhost origins in the production `ALLOWED_ORIGINS`.
- Token comparison with `===` instead of a constant-time compare.
- `[[url]]` links in diagrams are not intercepted on click.

## Usability and clarity

From the browser walkthrough.

### U1. Medium: the class connect handle covers class names (verified)

**Where:** `apps/web/src/ClassDiagramPreview.tsx:223`.

**Cause:** the blue handle is placed 10 px inside the entity's right edge, on the header row, so "OrderLine" reads "OrderLi●". Sequence fragment handles overlap the `alt` label in the same way.

**Fix:** place the handle just outside the box (`x + width + 6`), or show it only on hover or selection.

### U2. Medium: Note fields are mislabelled for assistive tech and clicks (verified)

**Where:** `TaskInspector.tsx:450`, `MilestoneInspector.tsx:164`, `DependencyInspector.tsx:140`.

**Cause:** the "Remove note" button sits inside the `<label>`. The label therefore targets the button, and the textarea has no accessible name. Clicking "Note" does not focus the field.

**Fix:** move the button out of the label, or use `htmlFor` with an id.

**Related:** labels that wrap a `<select>` read every option as part of the name ("Durationdaysweeksmonths", "Linked taskNo dependency…"), and the duration unit select has no name.

### U3. Medium: opening the inspector crushes the preview

At 1440 px wide, the Task inspector leaves about 200 px for the preview. The preview toolbar (Navigate, Preview zoom, Overlays, Forecast, Timeline scale, Move policy, Filter) wraps into a five-row stack, and the chart is clipped.

**Fix:**

- Collapse secondary preview controls into a "View" popover when the pane is narrow.
- Let the inspector overlay the code pane instead of the preview, or make the split resizable.

### U4. Medium: syntax errors show raw engine text over the controls

**What happens:** typing `[Testing] lasts banana days` shows a floating card reading "Syntax Error? (Assumed diagram type: gantt) — line 6 …". It also offers a "Retry rendering" button that cannot help, and it covers the zoom and overlay controls.

**Fix:**

- Show a plain-language hint when the parser can name the problem ("`banana` isn't a duration — try `lasts 5 days`").
- Offer "Go to line 6" instead of Retry for syntax errors.
- Dock the notice below the toolbar so it doesn't cover it.

### U5. Low–Med: the top menu bar changes between diagram types

Gantt tabs show **File · Save · Plan · Commands · Collaborate · More**; other tabs drop **Plan**, so Commands and Collaborate move left. Users lose their spatial memory when switching tabs.

**Fix:** keep Plan visible but disabled, with a tooltip saying "Gantt documents only".

### U6. Low: smaller polish

- **Tab titles:** they truncate early ("Sequence d…") even with plenty of room. Widen the max width, or shrink only when tabs overflow.
- **Small diagrams:** they open at 100 % in a large empty pane. Fit-to-pane on first open would make small diagrams readable.
- **Inspector close:** it has both an × and a Close button; one is enough.
- **Wording:** the same view is called "Tasks" on desktop and "Task list" on mobile. Pick one.
- **Hint banner:** the persistent "Use Add for a new task…" banner takes a full row. Show it once per diagram type, then put it under Editing help.
- **Mobile:** the undo/redo icons in the header are small touch targets, and the stray "▾" next to them is unlabelled visually.

### Ideas for a more enjoyable experience

- **Empty states that teach:** a new Gantt document could offer "Add your first task" inline in the preview rather than relying on the banner.
- **Inline error squiggles:** with a quick-fix, for the common Gantt mistakes (missing `days`, unknown task in `after [X]`). The parser already knows the line.
- **Celebrate progress check-ins:** after updating task progress on mobile, a brief "3 of 8 tasks done" summary makes the Task check-in feel rewarding.
