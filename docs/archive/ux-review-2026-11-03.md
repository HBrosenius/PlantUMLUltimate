# Usability review: PlantUML Ultimate web app

Reviewed: 2026-11-03 on `main` at `2623e452` (after #109, command ribbon). Local dev server, Chromium, 1440×900 desktop (dark and light) and 375×812 mobile (light). Flow covered: first-run chooser → new Gantt diagram → ribbon tabs → File menu → command palette → Diagram options → selecting a task on the canvas → task inspector → Help → mobile Task list and Diagram views.

Scope is the Gantt editing path, which is the most feature-rich. Other diagram types (WBS, Activity, Class, Sequence, Use Case, Component) share the shell and most findings apply to them too, but their canvases were not walked.

## Summary

The app is capable and the core loop works well: clicking a bar selects it, highlights the matching source line, and opens an inspector; Help is contextual to the current diagram type; nothing overflows horizontally on a phone. The main usability cost is **density and duplication**. The same command often lives in two or three places (top bar, ribbon, preview toolbar, Diagram options, command palette), explanatory text is always on screen instead of on demand, and several labels and commit models differ between panels. The biggest wins come from removing things, not adding them.

Top five, in order of impact:

1. Fit the diagram to the preview by default; the Gantt opens tiny in a large empty canvas.
2. Pick one home for each command and remove the duplicates (Undo/Redo, Diagram settings, Format source, Reports).
3. Use one commit model in inspectors (auto-apply) instead of Apply/Cancel in some and auto-save in others.
4. Move help text and hints out of the permanent layout.
5. Fix stale copy that still points to the removed **More** menu.

## Findings and suggestions

Priority: **P1** blocks or misleads users, **P2** slows them down or adds noise, **P3** polish.

### 8. Accessibility checks to follow up

These came up during the walk but need a proper pass:

- Insert ribbon buttons (Task, Milestone, Divider) were exposed without accessible names in the accessibility tree while the shortcut glyphs (⌥T, ⌥M, ⌥D) were shown. Confirm, and make sure the shortcut is in `aria-keyshortcuts`, not the name.
- Several labels are 10–11 px (ribbon group captions, editor toolbar buttons, Gantt day headers). Check contrast against WCAG AA on both themes; an automated pass flagged some of these but gave unreliable ratios on translucent backgrounds.
- Keyboard focus order between ribbon → document tabs → editor → preview → inspector was not walked.

## Suggested order of work

1. **Quick fixes (hours):** 1.1 stale "More" copy, 3.1 Fit by default, 3.3 move hint into Help, 5.3 checkbox labels, 2.4 disabled-button names.
2. **Consistency (days):** 5.1 single inspector commit model, 3.5 one name for the Task list, 4.2 switches for toggles, 2.2 Undo/Redo duplication, 3.6 contextual error navigation.
3. **Structure (a week or more):** 4.1 consolidate settings homes, 1.2–1.3 simplify the chooser, 6.2 mobile command sheet, 2.3 ribbon visual hierarchy, 7.1 Help landing page.
4. **Investigate:** 6.1 slow or stuck mobile render.
