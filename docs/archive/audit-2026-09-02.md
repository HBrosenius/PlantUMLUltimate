# Security and Engineering Audit — 2026-09-02

Read-only review of the PlantUML Ultimate monorepo (web app, collaboration Worker, integration Worker, shared packages, CI/CD). No code was changed. Findings are for further analysis and prioritisation; nothing here has been fixed.

Severity scale: **Critical** (exploitable now, high impact) · **High** (likely exploitable or severe operational risk) · **Medium** (real weakness, needs preconditions) · **Low** (hardening) · **Info** (observation). Items marked _needs confirmation_ were not fully verifiable from source alone.

---

## 1. Executive summary

The codebase is in good shape overall: strict TypeScript everywhere, zero `any`, parameterised SQL, tokens encrypted at rest, DOMPurify on rendered SVG, origin-checked postMessage, capability-based collaboration with server-side viewer enforcement, and a self-hosted renderer with no third-party scripts or telemetry.

The most important issues are concentrated in the **collaboration service** and the **trust boundary around shared links**:

| #   | Finding                                                                                                                        | Severity | Area                |
| --- | ------------------------------------------------------------------------------------------------------------------------------ | -------- | ------------------- |
| S1  | Collaboration tokens (incl. owner token) sent in WebSocket query string and logged at 100 % sampling                           | High     | Collab worker + web |
| S2  | Anyone can create unbounded Durable Objects; first connection to an untokened room gets editor rights; legacy rooms hijackable | Medium   | Collab worker       |
| S3  | Crafted collaboration link rewrites the user's default server and leaks the active document                                    | Medium   | Web                 |
| S4  | Renderer iframe is same-origin with no `sandbox`; remote `!include` may be reachable                                           | Medium   | Web                 |
| S5  | CSP uses `'unsafe-inline'` scripts, is meta-only (no `frame-ancestors`), no security headers from host                         | Medium   | Web / hosting       |
| S6  | Revocation silently no-ops when owner is offline while UI reports success                                                      | Medium   | Web + collab worker |
| S7  | Integration worker: token refresh/decrypt failure turns every route (incl. disconnect) into 503                                | Medium   | Integration worker  |
| S8  | No rate limiting on either Worker; presence/reconnect amplification; unauthenticated D1 writes                                 | Medium   | Both workers        |
| G1  | Production deploy to Pages is not gated on the cross-browser suite; README claims it is                                        | High     | CI/CD               |
| G2  | `LICENSE` is a truncated MIT (liability paragraph missing)                                                                     | High     | Legal               |
| G3  | `App.tsx` is a 5,388-line component with ~80 state hooks and no unit tests                                                     | High     | Maintainability     |

Recommended order of work: S1 → S2/S3 → G1/G2 → S4/S5/S6 → S7/S8 → remaining Medium/Low.

## 2. Security findings

### 2.1 Collaboration Worker (`apps/collaboration-worker`) and client (`apps/web/src/collaboration.ts`)

**S1 — Capability tokens travel in the WebSocket URL and are logged. High.**
`collaboration.ts:33-39` builds the upgrade URL with `participant`, `access`, `owner`, `editor`, `viewer` as query parameters; the Worker reads them from `url.searchParams` (`index.ts:165-167, 185`). The owner client sends all three tokens on every connection and reconnect, not only at creation. `wrangler.jsonc:17` has `"logs": { "enabled": true, "head_sampling_rate": 1 }`, and Workers Logs record `request.url`. Every active room's full credential set therefore lands in Cloudflare logs (and any proxy logs). Fix: send credentials as the first message after upgrade (socket stays unauthenticated until validated) or via `Sec-WebSocket-Protocol`; send `owner/editor/viewer` only on the creation connection; lower log sampling or redact the query until fixed.

**S2 — Unbounded room creation, unauthenticated editor, hijackable legacy rooms. Medium.**
Any `/rooms/<43 chars>` request with an allowed `Origin` header (trivially forged outside a browser) creates a SQLite-backed Durable Object and persists a row before any credential check (`index.ts:81-121, 300-304`). The role resolution at `index.ts:193-194` grants **editor** to a connection with no credentials when the room has no tokens. A room with no owner token can be claimed by whoever first supplies all three tokens (`index.ts:169-184`); the migration code at `index.ts:99-106` implies such legacy rooms exist (_needs confirmation_). The claimer can then revoke the room and delete the document. No alarm/TTL deletes idle or revoked rooms (`index.ts:226-228`); on wake with `revoked = 1` the code re-persists an empty state (`index.ts:119-120`). Fix: require the creation credential set on the first-ever connection and refuse to `persist()` otherwise; reject `owner/editor/viewer` params on an already-populated room; add `storage.setAlarm` → `deleteAll()` for idle/revoked rooms.

**S3 — Collaboration link with `server=` rewrites the user's default server and leaks the document. Medium.**
The link fragment may carry `server` (`collaboration.ts:80-88`); it pre-fills the join dialog (`App.tsx:2056-2064`, `CollaborationDialog.tsx:38,44`) and on any submit, including Join, is persisted as the default (`CollaborationDialog.tsx:186` → `localStorage["plantuml-studio.collaboration-server"]`). Because a link without `access` makes the client treat itself as seeding editor (`collaboration.ts:171-173`), one click sends the currently active document's full source to the attacker's server; every room the victim later _creates_ also goes there together with its fresh tokens. Endpoint validation only requires http(s) (`App.tsx:1957-1963`) and CSP allows `connect-src https: wss: ws:`. Fix: never persist a link-supplied endpoint; warn prominently when it differs from the default; require `https:`/`wss:`; do not seed a room unless the owner token is present.

**S6 — Revocation is fire-and-forget. Medium.**
`collaboration.ts:230` returns silently if the socket is not `OPEN`; `App.tsx:2049-2053` then calls `stop()`, starts a new room and reports "Old collaboration link revoked". If the owner was reconnecting, the old room stays live. Fix: make revocation an awaited HTTP call (`POST /rooms/:id/revoke` with owner token in a header) or wait for a server ack before rotating.

**S8a — No rate limiting; presence amplification. Medium.**
Every `presence` message triggers a full participant-list broadcast to every socket (`index.ts:144-154, 232-240`) — O(N²) bytes per message, available to viewer credentials. No cap on connections per room or per participant. Every update re-encodes the full document twice and writes the full state to SQLite (`index.ts:251-260`); every (re)connect sends the full document to the client and the editor echoes its full state which is re-broadcast to all peers (`index.ts:207, 263-267`; `collaboration.ts:173`). Fix: cap connections per room, token-bucket per socket, coalesce presence broadcasts, adopt `y-protocols` sync/awareness (state-vector diffs) and incremental persistence.

**Low / Info (collaboration)**

- Participant `id` is client-chosen (`index.ts:199`); spoofing hides cursors from a target, collides React keys and mis-attributes version-history authorship (`App.tsx:1916-1920, 4099`). Server-assign ids.
- Token comparisons use `===` (`index.ts:186-191, 223`); use `crypto.subtle.timingSafeEqual`.
- Malformed Yjs update is not rolled back to `previousState` in the `catch` (`index.ts:250-274`). _Needs confirmation_ of Yjs partial-apply behaviour.
- Server-provided participant `color` is interpolated into a raw `style` attribute (`CodeEditor.tsx:58, 61, 91`; also `CollaborationDialog.tsx:153`, `VersionHistoryDialog.tsx:185`); validation exists only server-side, and the server is user-configurable (S3). A malicious server or peer can overlay the viewport with CSS. Validate `/^#[0-9a-f]{6}$/i` on the client and set styles via CSSOM.
- Editor link including the access token is written to the address bar (`App.tsx:2040-2041`) and thus browser history/sync/screenshots. Acceptable trade-off; document it or keep the token in memory and strip it from the visible URL.
- Production `ALLOWED_ORIGINS` includes `http://localhost:5173` and `http://127.0.0.1:5173` (`wrangler.jsonc:13`). Use wrangler `env` blocks.
- Room existence is distinguishable by status code (410/403/101); harmless with 256-bit ids.
- Update frames rely on ordering between two separate sends (`update-author` then update, `index.ts:266-267`); frame them together.
- `room_state.revision` is written but never read.

### 2.2 Integration Worker (`apps/integration-worker`) and Jira client

**S7 — Refresh/decrypt failure makes every `/api/*` route return 503. Medium.**
`sessionFor` (`index.ts:256-263`) runs before route dispatch and calls `refreshTokens`; if Atlassian has rotated/revoked the refresh token, the token endpoint is down, or `TOKEN_ENCRYPTION_KEY` was rotated, the outer handler returns 503. `/api/disconnect` can then never succeed (encrypted tokens stay in D1 up to 90 days) and `/api/connection` reports an outage rather than "reconnect" (client only special-cases `(401)`, `jira-client.ts:65`). Fix: treat decrypt failure and permanent refresh errors as "session invalid" (delete row, clear cookie, 401); refresh lazily only in routes that call upstream; distinguish transient 5xx from permanent 4xx.

**S8b — Unauthenticated D1 writes and per-request cleanup; no rate limiting. Medium.**
`GET /oauth/start` inserts a row for any anonymous caller (`index.ts:108-119`); every request — including 403/404s — runs two `DELETE` statements via `waitUntil` (`index.ts:441-446`). Write-amplification/cost DoS. Fix: Cloudflare rate-limit rule or Workers Rate Limiting binding; move cleanup to a cron trigger.

**Medium (UX) — OAuth denial path returns raw JSON in the popup.** When the user cancels at Atlassian, the callback has `state` + `error` but no `code`; `index.ts:179-182` returns `{"error":"Invalid OAuth callback"}` and the popup stays open, the opener never gets a message, the state row and temp cookie linger. Fix: if state + cookie validate, consume and redirect with `jira=error` regardless of `code`.

**Low**

- Malformed JSON body shapes (`null`, string, array) pass `limitedJson` and throw on property access → 503 instead of 400 (`index.ts:320-334, 361-372`; also `.filter` on upstream at `:314`).
- No PKCE in the authorization request (`index.ts:121-130`). Confidential client with single-use, cookie-bound state mitigates; add PKCE if Atlassian supports it (_needs confirmation_).
- Pre-auth cookie value is reused as the post-auth session id (`index.ts:113, 207, 300-305`); no rotation on privilege change. Reconnecting leaves the old session row (live tokens) until expiry; disconnect does not revoke upstream (_needs confirmation_ of an Atlassian revocation endpoint).
- Cookies are HttpOnly/SameSite=Lax/host-only but not `__Host-` prefixed (`index.ts:68-70`); a sibling subdomain could cookie-toss.
- Production `ALLOWED_ORIGINS` includes localhost origins (`wrangler.jsonc:21`), contradicting the worker README. Design silently depends on Worker and app being same-site.
- Upstream statuses passed through verbatim with generic messages; the local 403 from `jiraFetch` is indistinguishable from Jira's (`index.ts:277, 310, 350, 404-409`). Non-standard status → `Response.json` `RangeError` → 503.
- Possible refresh-token race: two concurrent requests near expiry both refresh with the same rotating refresh token (`JiraDialog.tsx:98, 138`; `index.ts:222, 241`). _Needs confirmation_ of Atlassian grace window.
- No `Cache-Control: no-store` / `X-Content-Type-Options: nosniff` on `/api/*` responses; no `Access-Control-Max-Age` on preflight.
- `accessible-resources` list is cached for the 90-day session (`index.ts:160-167, 267-269`).
- `deploy-integration.yml:16-18` uses `cancel-in-progress: true`, which can cancel between "Apply D1 migrations" and "Deploy".

**Info**

- AES-GCM without AAD (`crypto.ts:26-40`); bind ciphertext to `session_hash`. Key re-imported per call.
- Jira endpoint overridable via `localStorage["plantuml-studio.jira-integration-server"]` with no UI (`App.tsx:1872-1875`); same pattern for the collaboration server. Any future XSS could persist a phishing OAuth origin. Gate behind a dev flag.
- `JiraDialog.tsx:150-154` `window.open` without `noopener`.
- `wrangler.jsonc`: verify `"secrets": { "required": [...] }` is honoured by the wrangler version in use; `nodejs_compat` flag appears unnecessary.

### 2.3 Web application (`apps/web`)

**S4 — Renderer iframe is same-origin and unsandboxed. Medium.**
`render/use-renderer.ts:180-185` creates a `srcdoc` iframe with no `sandbox`; it runs the TeaVM-compiled PlantUML engine and Graphviz on untrusted input (shared files, collaboration rooms, backups) with full access to the app's origin, IndexedDB and localStorage. The engine bundle contains an XHR client and `!include`/`!includeurl`/`!theme … from` handling; whether remote includes actually work in this build is _needs confirmation_ — if so, opening a shared diagram triggers requests to attacker URLs (tracking/IP disclosure). Also: a pathological diagram blocks the main thread up to the 15 s timeout, and the frame is only rebuilt on `bootstrap-error`, not on timeout (`use-renderer.ts:99-112`). `render/renderer.worker.ts` is unreferenced dead code. Fix: `sandbox="allow-scripts"` with a `MessageChannel` handshake (or separate origin); strip `!include*`/`!import`/`!theme … from` in `render/plantuml-source.ts`; recreate the frame after timeout; remove or wire up the worker.

**S5 — CSP and host headers. Medium.**
`index.html:6-9`: `script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'` — `'unsafe-inline'` exists only for the inline renderer bootstrap (`use-renderer.ts:36-62`) and largely neutralises script-src. Meta CSP cannot set `frame-ancestors`, so clickjacking of Join/Restore flows is possible; GitHub Pages sends no `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP or HSTS. `connect-src https: wss: ws:` allows any host and plaintext WS (enables S3). Fix: move the bootstrap to static `/renderer-frame.html` + `.js` and drop `'unsafe-inline'`; add `<meta name="referrer" content="no-referrer">`; front Pages with Cloudflare to add headers; tighten `connect-src`.

**Medium — Inline `<style>` from SVG applies to the whole document.**
`render/sanitize-svg.ts:4-8` forbids `script`, `foreignObject`, `iframe`, `object`, `embed` but the DOMPurify SVG profile allows `<style>`; the result is injected via `dangerouslySetInnerHTML` in seven previews. A `<style>` inside inline SVG restyles the entire app (fake dialogs, hidden warnings). Whether attacker-controlled CSS can reach a `<style>` element through the PlantUML engine is _needs confirmation_. Fix: add `style` to `FORBID_TAGS` or render SVG inside a Shadow DOM.

**Medium-Low — Backup restore writes unvalidated version records to IndexedDB.**
`workspace-backup.ts:47-52` normalises the session but passes `versions` through untouched; `workspace-storage.ts:407-418` `put`s each record. Downstream code assumes `createdAt`, `reason`, `source` strings (`workspace-storage.ts:298`; `VersionHistoryDialog.tsx:11, 124`), so a malformed backup breaks every subsequent save and the history dialog until IndexedDB is cleared; truthy `pinned` blocks pruning; arbitrary `historyId` attaches versions to other documents. `viewMode`/`theme` are also unvalidated (`workspace-storage.ts:163, 165`; `App.tsx:3784`). Fix: schema-validate each version and enum fields; only import versions whose `historyId` belongs to the restored session.

**Low**

- Service worker caches any navigation response as `/index.html` without checking `response.ok` (`vite.config.ts:32`); a 404/5xx can poison the offline fallback.
- Sanitisation happens once at receipt (`use-renderer.ts:158`); SVG is then XML-round-tripped and string-patched several times before insertion (`canonical-gantt-overlay.ts:133, 659`; `legend.ts:68, 80`; `schedule-analysis.ts:274, 353`; `DiagramPreview.tsx:228-248`). No injection found, but classic mXSS shape; sanitise again immediately before insertion and add unit tests for `sanitizeSvg` (none exist).
- `App.tsx:438` casts a `localStorage` value without validation and without try/catch (throws in some privacy modes).
- Legacy `normalizeWorkspace` spreads unknown keys from stored JSON (`workspace-storage.ts:113-115`).
- Download filenames come from user/backup-controlled `fileName` (`file-service.ts:142, 195`; `App.tsx:2115`); a backup can produce an `.html` download.
- SVG `<a href>` from `[[url]]` survives sanitisation (javascript: blocked, `target` stripped); consider intercepting clicks and opening with `noopener` after confirmation.

### 2.4 Cross-cutting security/CI

- All GitHub Actions are referenced by mutable tag (`@v4`, `@v3`) in every workflow; pin to commit SHAs.
- No `SECURITY.md`, `dependabot.yml`/`renovate.json`, or `npm audit` step — notable for an app handling OAuth tokens and collaboration credentials.
- Worker deploys are gated on unit tests and typecheck but not on the collaboration Playwright suite; no staging environment.

## 3. General engineering findings

### High

**G1 — Production deploy is not gated on the browser suite; docs say it is.** `deploy-pages.yml` runs `npm run validate` + `test:e2e:pwa` only, then deploys. The Chromium/Firefox/WebKit matrix and collaboration e2e live in `ci.yml`, which triggers on `push: branches-ignore: [main]` and `pull_request` — never on `main`. `README.md:361, 414` claim otherwise. Whether branch protection requires PR CI is _needs confirmation_. Fix: gate via `workflow_run`/`needs`, or correct the README. Same gap in `release.yml` and both Worker deploys.

**G2 — `LICENSE` is truncated.** Ends after "FITNESS FOR A PARTICULAR PURPOSE AND NONINFRINGEMENT."; the "IN NO EVENT SHALL THE AUTHORS…" liability paragraph is missing. Replace with the full OSI MIT text.

**G3 — `App.tsx` god component.** 5,388 lines, ~80 `useState`, 20 `useEffect`, 134 `useCallback/useMemo`, two `exhaustive-deps` disables (`:864, :888`), no unit tests. Extract per-diagram feature hooks and dialog/selection reducers; `docs/architecture.md` already points this way.

### Medium

- **Package manager inconsistency.** `package.json` pins `packageManager: npm@11.17.0` with npm workspaces and `package-lock.json`; a `pnpm-workspace.yaml` also exists (no `pnpm-lock.yaml`); README says "npm 10 or newer"; no `engines` or `.nvmrc`.
- **Undeclared workspace dependencies.** `diagram-class`, `diagram-usecase`, `diagram-wbs` import `@plantuml-studio/language-core` (wbs also `language-plantuml`) with no `dependencies`; `diagram-sequence` declares none. Manifests mix `exports` vs `main`/`types`. `diagram-gantt` and `editor-core` pin `vitest ^3.2.4` while root uses `^4.1.11` — two vitest majors installed.
- **ADR 0002 adapter architecture only partially realised.** Only gantt and wbs implement `DiagramAdapter`; `DiagramAdapterRegistry` is used only in a test; `wbsAdapter` is never imported by app code; diagram-kind detection is re-implemented with regexes in `apps/web/src/diagram-kind.ts`. Sequence/class/usecase/wbs operations return whole strings, and the wbs adapter wraps them as full-document replace edits, contradicting the "minimal source edits" principle. Either wire the registry in or amend the ADR.
- **Test coverage.** No React component tests (all 40 web tests are pure logic); UI covered only by Playwright, with `tests/e2e/editor.spec.ts` at 3,692 lines / 113 tests in one file. `language-core` and `language-plantuml` have zero tests. No coverage tooling or thresholds. `applySourceEdits` (generic) lives in `diagram-gantt` rather than `language-core`. Worker test gaps: callback error paths, refresh/decrypt failure, size limits, hibernation with revoked flag, legacy-room claim, presence limits; `CollaborationSession` client logic untested; `crypto.ts` has no direct tests; `JiraDialog`/popup flow untested.
- **Wall-clock assertions in the unit suite.** `apps/web/src/performance.test.ts` asserts `< 100/30/250 ms` and runs in `validate` — flaky on loaded CI. Move to `benchmarks/`.
- **No dependency automation / health files.** No Dependabot/Renovate, CODEOWNERS, SECURITY.md, CONTRIBUTING.md, issue templates. `@cloudflare/workers-types` and `yjs` ranges already drift between workers.
- **Placeholder packages.** `packages/diagram-ui`, `renderer`, `shared`, `ui` contain only a README; their described code lives in `apps/web/src`. Delete or realise (renderer is the best candidate).
- **Documentation drift.** README repo map omits `jira-integration` and both Workers and never mentions Jira at all (a 0.2.0 headline feature); `npm test` labelled "unit tests" but runs Worker suites too; integration README says "replace the placeholder `database_id`" though a real ID is committed; `docs/architecture.md` covers only gantt/wbs; `docs/persistence-and-files.md` predates version history/backups; rendering docs omit sanitisation and the same-origin frame threat model.
- **`diagram-sequence` is a single 1,168-line module** unlike its siblings; five near-identical `*SymbolOccurrence` interfaces duplicated across packages — lift a generic into `language-core`.

### Low

- `tests/e2e`, `benchmarks/`, and root configs are not type-checked (no root `tsconfig.json`; ~4,200 lines of Playwright specs unchecked).
- Single 3,878-line `styles.css`; flat `apps/web/src` with ~150 files and one subfolder.
- `@typescript-eslint/no-explicit-any` is disabled (`eslint.config.js:18`) although there are zero `any` usages — re-enable to lock it in. `exhaustive-deps` and `only-export-components` are `warn` only.
- Duplicate `CNAME` (root and `apps/web/public`); root copy is dead.
- `wbsAdapter.parse` parses twice (`packages/diagram-wbs/src/adapter.ts:33`).
- Release workflow does not verify tag == `package.json` version or use `CHANGELOG.md`; no version-bump automation.
- Vitest config duplicates env bindings (`apps/integration-worker/vitest.config.ts:5-6` vs `:15-17`).
- `apiRequest` is a 130-line if-chain; `jiraFetch` mixes local-403 and upstream response types; `jira-client.ts:65` detects auth state by string-matching `"(401)"`.
- Client Jira `startFieldId` may be any date field, but the server accepts only `customfield_N` → whole batch fails with generic 400.
- `<textarea required>` in `JiraDialog.tsx:594` has no effect (no `<form>`).

### Info

- `@plantuml/core` is exact-pinned to `1.2026.6`, the first MIT release (earlier versions GPL-3.0) — good; document why it must stay exact. Viz.js/Graphviz attribution/notice obligations are not surfaced (no THIRD-PARTY/NOTICE file) — _needs confirmation_.
- All UI strings hard-coded English; no i18n layer.
- Good a11y baseline (541 `aria-*`/`role` uses, dialog focus hook, keyboard table) but no automated axe check in Playwright.
- Service worker precaches every emitted file including the multi-MB renderer, so first load equals the full payload; consider caching engine assets on first render instead.
- No WebSocket heartbeats (`setWebSocketAutoResponse`) for faster dead-connection detection.

## 4. What is done well

- Strict TS (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`); zero `any`, zero `@ts-ignore`, zero TODO/FIXME, four `eslint-disable`s in total.
- No third-party scripts, CDNs, fonts or telemetry; `default-src 'self'`, `object-src 'none'`, `base-uri 'none'`.
- Rendered SVG sanitised with current DOMPurify; postMessage checked in both directions with per-instance channel ids and `event.source` checks; overlays built with DOM APIs, not string concatenation.
- Collaboration: 256-bit room ids/tokens from `getRandomValues`, kept in URL fragments for share links; separate owner/editor/viewer capabilities; viewer writes rejected server-side for every binary frame (unit + e2e tested); revocation requires owner attachment plus owner token; hibernation API used correctly; sensible size caps with rollback.
- Integration worker: single-use, hashed, TTL-bound, cookie-bound OAuth state; `return_url` exact-origin allowlist; tokens never reach the browser and are AES-GCM encrypted at rest with hashed session ids; all SQL parameterised; fixed upstream host (no SSRF); strict allowlists on write payloads; streaming body limits; structured error logging without secrets.
- CI: `permissions: contents: read` everywhere, concurrency groups, 3-browser sharded matrix with failure artifacts, PWA offline smoke test, live-Worker collaboration e2e, Worker tests against real DO/D1 bindings.
- Clean acyclic package graph; consistent 0.2.0 versioning; Keep-a-Changelog; six concise ADRs.

## 5. Suggested next steps

1. Fix S1 (tokens out of the URL, reduce log sampling) — highest confidentiality impact and cheapest to ship.
2. Close S2/S3 (creation requires credentials, no link-persisted server, no seeding without owner token).
3. Correct G1 and G2 (deploy gating + full LICENSE).
4. Harden the renderer (S4) and CSP/headers (S5); decide on the `<style>` question.
5. Make revocation awaited (S6); fix the integration worker 503 path (S7); add rate limiting on both Workers (S8).
6. Schedule the engineering debt: App.tsx decomposition, package manifests, adapter architecture decision, test coverage, docs refresh, Dependabot + SHA-pinned actions.
