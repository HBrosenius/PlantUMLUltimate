# Persistence and files

Each page has an independent recovery identity retained in navigation state for reloads. Synchronous local journals and IndexedDB snapshots include save ordering metadata; recovery selects the newest copy for that page, with legacy/shared copies available for migration and new pages. Up to 100 recent workspace snapshots are retained. Active-project recovery and its closed state are also scoped to the page. Database initialization and recovery are bounded, and editable controls wait for hydration. Database writes are debounced by 350 ms; synchronous workspace journals update with session changes. Recovery includes source, filename, dirty state, view mode, split position, zoom, cursor position, and theme. If IndexedDB is unavailable, the application falls back to local storage and reports the actual recovery backend.

Open accepts portable `.pumlu` documents and legacy `.puml`/`.plantuml` source. Browsers with the File System Access API use native Open, Save, and Save As handles. Other browsers use a file upload for Open and downloads for Save As. Native file handles are intentionally held only for the current browser session. Encrypted documents keep unlocked plaintext only in memory and must be saved before closing.

Save completion targets the captured document and leaves newer edits dirty. Overlapping file operations for a document are blocked. Password protection removes plaintext workspace copies, including page journals; obsolete writes cannot reintroduce excluded plaintext. SVG export requires a successful render belonging to the active document and current source. PlantUML source export always downloads the current source.
