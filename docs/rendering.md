# Rendering

The application renders canonical SVG with the official `@plantuml/core` browser build. Trusted engine assets are loaded lazily and run in a terminable worker inside a sandboxed iframe. The frame has no access to the application's origin or storage and its CSP blocks network requests. Text is measured on demand with worker-local OffscreenCanvas when available. A bounded browser font atlas supplies measurements when worker canvas is unavailable or document web fonts are present. Graphviz is loaded for diagram types that require it; bundled OpenIconic sprites remain available. No source is sent to a rendering server.

The renderer serializes requests, matches replies to the in-flight request, debounces edits by 150 ms, and caches up to 50 successful results within a 20 MB budget. Results carry document and source ownership; export requires a successful matching result. Startup has a 15-second deadline and one automatic retry. Rendering has a 30-second deadline that terminates the worker, including CPU-bound engine work. Syntax failures remain visible as errors while a same-document previous preview can be retained. Successful renders reuse a warm worker within one document, recycling it after 20 renders. Switching documents, errors, retries and timeouts replace the worker. Font contexts are rebuilt for each render. Browser regressions compare warm SVGs against fresh engines after font and style changes.

The sandbox bootstrap is small; trusted engine assets arrive in an authenticated parent-window message rather than being encoded a second time into iframe HTML. Font measurement yields after an elapsed work budget, avoiding unnecessary message turns for cached measurements. Fallback font metric buffers transfer to the worker without copying. Trusted scripts have short diagnostic names to avoid copying multi-megabyte data URLs into routine engine exception stacks. These changes preserve the opaque origin, network-blocking CSP, SVG sanitization and render deadlines.

PlantUML SVG does not expose stable semantic task IDs. A derived, disposable overlay matches parsed task labels to canonical Gantt bar geometry and adds transparent interaction targets for selection, dragging, resizing, and dependency operations. PlantUML source remains the only persistent document representation.
