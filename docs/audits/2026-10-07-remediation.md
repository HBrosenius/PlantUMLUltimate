# Security and stability remediation — 2026-10-07

> A subsequent [rendering performance follow-up](2026-10-07-rendering-performance.md) replaces per-render worker creation with bounded, document-scoped reuse, verifies output against fresh engines, and retains isolation and timeout protections. The remediation record below describes the initial fixes.

Changes are applied locally to PlantUML Ultimate **0.2.0**, based on **`7f25b1f648ea9f2770ef7d0f237950a70df854ac`**. A second `git fetch origin` confirmed this base remained **0 ahead / 0 behind**. Nothing was deployed or committed. The pre-existing `allowScripts` preference is preserved.

All 14 findings in the [fresh audit](../../SECURITY_STABILITY_AUDIT.md) have corresponding fixes. The original audit remains a record of the defects before remediation; its reproduction probes deliberately assert defective behavior and are not post-fix regression tests.

## Remaining limits

- **Cold-start performance:** the engine remains large. A clean local WebKit run took about 24 seconds to display its first Gantt SVG, with about 11 seconds attributed to the engine render. Both native and Graphviz work under CSP, but this is not a claim that rendering is fast in every browser. Worker initialization and font measurement add overhead; subsequent requests use bounded caches and prewarming.
- Worker termination prevents a stuck render from holding the editor's main thread. There is no application-enforced worker heap quota or exhaustive third-party engine fuzzing. Font metrics supplied to the virtual DOM may produce small layout differences.
- New invalid collaboration updates are rejected. Previously corrupted production room state, if any exists, would need administrative recovery; no production data was inspected or migrated.
- Recovery is bounded and more reliable, but abrupt process/storage failure can still lose unsaved work. Independently restoring a page requires its navigation recovery identity; clearing it falls back to shared recovery. Save files and backups remain important.
- The CSP response header was simulated locally. Actual hosting headers, live Jira integrations, deployment configuration and the complete end-to-end/PWA suite were not verified in this remediation run.
